# Доска заданий ученика и флоу преподавателя

Дата: 2026-11-03. Статус: утверждено в чате 2026-11-03 («да» на описание ниже).
Образцы: доска — `admin_panel/src/components/backlog/GitlabTaskBoard.tsx` (колонки-этапы со счётчиком, карточки
с точкой, номером, заголовком, метками и кружком исполнителя, перенос мышью); флоу — DocOps «Настройки → Флоу»
(этапы, переходы).

## Флоу (преподаватель, «Настройки → Флоу»)
- Один флоу на тренажёр: этапы по порядку и разрешённые переходы между ними (вперёд и возвраты).
- Первый этап `todo` («К выполнению») и последний `done` («Готово») — постоянные; между ними — свои этапы.
- У этапа — название и агент, который ведёт задание на этом этапе; пусто — агент задания, выбранный методистом.
- По умолчанию: К выполнению → Анализ (системный аналитик) → Разработка (агент задания) → Ревью (техлид) → Готово;
  возвраты Ревью → Разработка → Анализ.
- Проверка флоу: ключи уникальны; переходы — между существующими этапами; в `todo` не входят, из `done` не выходят;
  в `done` есть хотя бы один переход; каждый этап достижим из `todo`.

## Доска (ученик — вместо списка заданий; преподаватель — по каждому ученику со страницы «Группа»)
- Колонки — этапы флоу со счётчиком; карточка: номер, заголовок, урок, кружок агента этапа, точка состояния
  (ждёт тебя / агент думает / готово / не начато). Нажатие — чат задания.
- Ученик переносит карточку только по разрешённым переходам (мышью или меню «Перенести»); преподаватель — в любой
  этап, кроме `todo`, и не из `done`.
- Перенос в рабочий этап: этап меняется, задание подхватывает агент этапа (новый ход тьютора, в чате — отметка этапа).
- Перенос в `done`: запускаются проверочные команды; все прошли — задание готово; нет — карточка остаётся, в чате —
  что не прошло, и агент этапа объясняет (ход тьютора).
- Ход тьютора сам закрывает задание (все проверки прошли) только на этапе, из которого есть переход в `done`.
- Задания без этапа (созданы до флоу) и этапы, удалённые из флоу: этап выводится из статуса
  (`todo` → «К выполнению», `done` → «Готово», иначе — первый рабочий этап).

## Мои решения
- Флоу хранится одним JSON-документом (как политика DocOps), без версий.
- Перенос — нативный drag-and-drop браузера и меню на карточке (клавиатура/телефон), без новой библиотеки.
